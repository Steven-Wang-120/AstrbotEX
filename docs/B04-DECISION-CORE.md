# B04 decision core — implementation handoff (2026-09-30)

## Runtime authority and integration

`DecisionBackend.decide(snapshot: DecisionSnapshot) -> BackendDecision` is synchronous; `close()` must cooperatively release outstanding work. Types are the frozen `core.decision.models` models. MockBackend supports deterministic kind/owner choices, `entered`/`release` event latches, failure injection and close. B07 Jev/registry is now composed offline in this tree; no vendor API/paid call is made. The static immutable registry contains only `mock` and `jev`; imports/construction do not discover plugins or read a key.

`build_server()` creates an instance-local DecisionService, connects runtime/environment lifecycle and exposes its cached state under existing runtime status `actions`. Defaults remain control_mode=legacy, decision mode=disabled, closed Dispatcher gate. No new public management/transport endpoint is added; B05/B08 must call trusted service methods after authenticating the caller. Changing mode does not start runtime or install a goal. Start runtime, enable decision evaluation, then submit new authorized goal are separate operations.

- `submit_goal`, `cancel_goal`, `renew_goal` parse frozen requests. Request IDs have session-local, non-evicted SHA-256 tombstones. Goal + parameters and optional expected_revision CAS commit together.
- One active and at most one pending_replace; pending replacement supersedes prior pending, never queues steps. Admission revokes old gate immediately. The control worker asks ActionService for physical stop and committed proof, reviews Dispatcher stop state, then activates. Failed/unknown ownership stays blocked. Explicit `review().result()` discards all old authorization; a NEW submit is necessary.
- `request_stop` only revokes state/gate and signals the worker. Runtime stop/pause/fault and owner lifecycle use it; environment switch does likewise before transition. Existing ROS quiesce and ActionService proof remain authoritative. Snapshot restore goes through controller stop; EX restart creates a new session and no active goal.
- Completion is a nonempty declared required_success_actions set proven by current-session/current-revision committed succeeded rows with positive event sequence. It closes the gate and enters awaiting_llm. No model selects the next goal, and semantic completion is not inferred.

## Observation policy

Only declared topics are subscribed. Store copies original source-specific JSON, with no renamed business fields. ObservationEnvelope gets a generated ID, description/spec/guide/generation hash, receive monotonic timestamp, source epoch and sequence. A TopicBus message explicit payload `source_epoch` is used when present; otherwise trusted plugin generation supplies `owner:generation`. Source timestamp is the existing TopicMessage timestamp (wall seconds), seq is its existing seq. Missing sequence is rejected, missing/invalid/future/too-old source time is unhealthy. Neither a payload timestamp nor parser age alone grants freshness.

Old frames cannot advance current seq; retired epochs cannot become current. Bounded epoch records hold a receive sequence high-water mark independently of the cached frame. Guide/spec/generation updates and disable/re-enable clear frame data, but never erase that high-water mark or retired epochs. Disabled sources are not subscribed/admitted. A truly new epoch can start at a lower sequence; an old epoch cannot return. Unknown opaque boot epochs are trusted only as declared-source metadata, not cryptographic proof. Independent topic max_age_ms applies to receive age plus initial source age; no cross-topic atomic-time claim is made.

Both canonical `target_ref` and legacy `target` are recognized without modifying raw JSON. Canonical references require observation_id/source_epoch/stream_id/track_session/object_id; stream/frame comes from data root, unique object/session from data.objects[], sequence from the envelope. Optional frame_id/observation_seq companion fields are checked, not remapped. Two reference forms together, contradictory companions or duplicated object IDs are explicitly rejected. High-danger observed actions lacking a valid reference have no start candidate. New mismatching target data immediately revokes Dispatcher context before a queued Actor executes; apply independently rechecks even if update notification is suppressed.

Each response checks BOTH latest epoch/hash/health/target identity and its own request observations. Request age is conservatively old.age_ms + monotonic elapsed since old.received_monotonic_ns, against each current source spec's max_age_ms; missing/disabled source, changed description hash and clock regression fail closed. Fresh new frames cannot renew old request TTL. Dispatcher receives original request data with aged values, not latest replacement fields. Observation state is held only across the final short validation/context/start enqueue boundary (never SQLite/backend completion), closing the update-before-enqueue gap.

## Scheduling and execution

Two daemon threads per service: one serialized control/persistence coordinator, one backend thread. Only one live backend request exists. Flood updates set one dirty bit. Timed-out decide remains live until it returns or backend.close cooperates; no replacement threads/futures are spawned. Rate limiting, bounded exponential failure backoff and independent goal lease expiry apply. Backend receives a defensive contract copy, never the authoritative option mapping.

Runtime tick only signals. Status uses cached Ledger rows. Stop/gate transitions never wait for backend or SQLite under runtime locks. Ledger waits are on the control worker with bounded future timeouts. The environment snapshot is sampled outside decision state locks to avoid environment/decision inverse lock order.

Snapshot hard-filters starts by current goal authorization, exact parameters/schema, catalog availability, runtime state, observations/target, resources and block state. Wait/replan remain; existing keep/cancel bind command IDs. Keep never repeats or extends start. Every owner has one backend choice; invented options/owners/parameters cannot dispatch.

Return validation binds snapshot/session/goal/config/catalog/environment generation/plugin generations/Dispatcher gate epoch/age. Actual action admission goes through B02 update_context + start and retains its Actor execution guard. All selected starts arbitrate shared resources before submission. Admissions and later plugin rejections are observed separately. Partial execution is recorded, gate closes and prior peers cancel; it is never described as atomic success.

## Instance bounds and retention

Goal request tombstones: 4096 then refuse NEW requests (never evict/re-execute); goal diagnostic history 64; at most 128 authorized actions per goal, one active and one pending. Catalog max owners 256 inherited. Observation max sources ever seen 128, latest frame only per source, JSON <=65536 bytes, <=64 retired epochs per source; exceeding source/epoch budget fails closed and requires controlled new instance/session rather than forgetting old epochs. Snapshot max starts is limited by the goal's 128 actions; wait/cancel not silently removed. Decision history 128, partial-batch history 64, last backend ID history 64. Cached unresolved status shows at most 128 records (diagnostic only); Ledger scan limit 10000 fails closed. Two worker slots, one input/result/live backend slot and one coalescing update bit. These histories are diagnostics, not authorization or command-id dedupe.

`DecisionService.close()` revokes, signals closed, closes backend, requests/awaits stop proof, joins workers and releases topic subscriptions even if backend.close raises. Unproven physical stop remains visible as blocked; initial runtime/environment failed-stop shutdown still preserves action reporting rather than claiming stopped. After that proof stage, HTTP shutdown always attempts connections, DecisionService, ActionService and socket cleanup using nested finally; a single error is re-raised, multiple errors are reported as Python 3.10-compatible `ShutdownErrors` with an `.exceptions` tuple retaining the original exception objects (not just strings). Worker joins/subscription/socket cleanup errors also accumulate before raising. A backend that ignores close raises worker timeout; Python cannot kill its in-flight thread, but no replacement worker is created and a later cooperative release exits it.

`review()` keeps the normal cancelable Future interface. Cancel before worker claim succeeds and skips that review's stop/review side effects; a new review can replace that canceled slot. Worker claim uses set_running_or_notify_cancel, after which cancel returns false and committed review success/failure remains observable. Pending reviews receive a closed error during shutdown without InvalidStateError races; cancellation never bypasses independent safety stop requests.
