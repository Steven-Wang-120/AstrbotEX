# EX Chat 与 astrC 进度报告

日期：2026-11-11。原生客户端 0.2.1+5，arm64 Android versionCode 2005。本报告为当日最终状态；此前分阶段记录保留为历史证据。

## 当前架构与交付

人使用 astrC，本机生成密码保护的 Ed25519/X25519 身份；bot 使用 EX Chat 的持久身份。双方通过可替换的公网 HTTPS 加密邮箱互加好友及收发文字，EX 再通过 OneBot11 接 AstrBot 或其他 Agent。应用宝只作 Android 试机，不承担通信或中继职责。

已完成注册/解锁、加密备份、签名名片与二维码、好友申请和审批、文字私聊、固定密文待发、重启恢复、离线收件与 ACK 去重。登录页已去除电脑端口及旧副标题。旧 EX 数字账号、群聊、图片、@及引用留作兼容联调，不能视为新身份通道已支持相同能力。

本机 Docker 的 EX 已从隔离测试 bot 切至主 AstrBot，使用独立 OneBot 平台 `astrc_ex_main`。沿用同一 bot 身份与已有好友，主 bot 原模型、插件配置和原 QQ/NapCat、ZMQ 接入保留。聊天 runtime 保持 idle。邮箱服务已部署于独立节点，经 HTTPS 提供公网入口。

APK 对应客户端功能提交 `d5046c3bbac840b91a8964debb83cc1f5d55160c`；实际 EX 镜像功能提交 `4d6fa6ca50acd4cc793d56e14f62d0cea1708cd3`。后续报告和测试归档提交不要求重建已部署二进制。协议快照仍固定在其原始来源提交与文件哈希。

## 人格问题与修复

原人格「111」仍在 AstrBot 数据库中，但根配置 `provider_settings.default_personality` 为 `default`；当前会话没有其他人格覆盖，因此未注入原设定。接入主 bot 前的备份已是该值，现有记录不足以判断更早何时变更。

仅恢复默认选择为 `111`，与变更前配置逐字段比对，其他字段一致。容器实际 PersonaManager 与提示注入函数使用现有数据库验证通过：现有会话及新合成会话均选择原人格，注入内容与库中原文一致。该检查将技能和工具服务替身化，仅证明人格选择与注入，不证明全部插件工作正常。

重启时出现 SQLite disk I/O error；当时 Windows 只读诊断连接跨重启保持打开，诊断进程退出后服务恢复。尚未证明全部底层原因。数据库 quick_check 为 ok；后续 SQLite 诊断放在容器内并及时关闭连接。
