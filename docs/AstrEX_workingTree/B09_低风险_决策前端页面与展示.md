## 2. 五个区块与真实数据源

所有接口使用 `/api/v1/ex/decision` 前缀。

| 区块 | 映射及边界 |
|---|---|
| A 状态与控制 | `/status` 的 `decision/service/operations/model_quality`。显示模式、权限、门禁、blocked、会话/版本、服务代次、restart_required 和停止回执。保留 replan 0/8 限制 |
| B 配置与服务 | `/backends` 的实际能力，`/config` 的 saved/effective/secrets。固定地址、模型、revision、端口只读。保存、探测、模式、启动、停止、恢复分别操作 |
| C 当前 Goal | `/snapshot.current_goal/pending_goal/goal_phase`。使用 `goal_text_en`、task/step/goal ID 和 parameters。Goal 管理版本来自 `/status.decision.goals.revision` |
| D 实际决策 | `/snapshot.last_built/last_submitted/last_result` 分别展示。`/decisions` 提供分页、详情、实际正文、模型选择及 EX 结果 |
| E 动作与反馈 | `/actions` 的 Ledger 投影。显示 owner、状态、原因、资源、StopEvidence 和关联 Goal/请求。通用 details 安全文本折叠 |

页面不重建未采集的 Jev 正文。`null` 阶段标记显示“未知”。截断记录保留 `record_truncated`、`*_display` 和原始大小。

模型选择、EX 受理、Actor 接收、动作完成和停止证明分别显示。动作 succeeded 不等于整个 Goal 完成。失败动作补到停止证明后仍显示失败。blocked 与证明独立显示。

动作关联优先使用账本的 `decision_id` 和当前已取得的请求记录。没有匹配请求时，保留原始关联 ID，不伪造 request_id。事件集合按状态列出，不推测先后顺序。窗口不完整时提示部分历史不可见。

## 3. 配置与异步操作

配置仅覆盖服务端支持的 Mock、Jev、Laya 字段。密钥操作明确区分保留、设置和清除。密钥值不读回，提交及会话变化后清空输入。

- 保存配置不启动服务、不切换模式。
- 连接测试显示实际范围。Laya 的 GET /health 不是推理验收。
- 普通 Laya 和 Jev 的 execute 按 `/backends` 能力禁用。
- Laya 启动、停止服务和显式恢复分别调用已有接口。
- 恢复不会由页面恢复旧模式、提交旧 Goal 或重放命令。

普通写入带 `ex_session` 和 `expected_revision`。停止仅带当前会话，不受草稿及版本冲突阻塞。

409 保留草稿，不重发。用户可以“核对新版本，保留草稿”，也可以“放弃草稿并读取”。核对后仍需显式保存。

202 只表示已受理。页面约每 500 ms 查询当前页发起的 operation。识别 pending、running、succeeded、failed、blocked 和 superseded。404 显示记录不可查询、结果未知，并刷新当前状态。未知状态保留原值。

服务端只投影操作计数，没有全量 operation ID 列表。因此，页面刷新后不重建旧操作跟踪，也不猜测旧操作结果。

## 4. 凭据、刷新与旧响应

复用 `managementFetch()` 和已有 fetch SSE。凭据仅在页面内存，通过 Authorization 发送，不进入 URL 或浏览器存储。

`decision_changed` 只通知刷新。状态请求最多每秒合并一次，同类读取不重叠。操作查询使用独立轮询。隐藏页面暂停，离页中止读取并使旧读取失效。重新进入先读取当前状态。

请求校验会话、凭据代次、读取代次及管理/框架版本。会话或凭据改变后，清除旧操作、关联和有效配置版本。非敏感草稿保留，但核对新版本前不能提交。

读取期限为 10 秒。断线保留最近数据，标记已过期。恢复读取、页面加载、刷新及导航均不触发写入。已发出的写入不会被轮询重放。

所有外部文本使用 `textContent`。详细 JSON 默认折叠。没有新增导出、备份或训练集下载功能。

## 5. 未接入区域与后续边界

`decision.js` 的 `mapData()` 是针对 B08 的轻量映射，未建立通用适配框架。

| 区域 | 当前状态 | 后续接入条件 |
|---|---|---|
| A.E.B. 任务/步骤、等待输入/复核 | 未接入 | 后端提供已约定的 HTTP 投影 |
| 反馈序号、反馈状态、完成证据 | 未接入 | 不能把反馈 ACK 当作任务成功 |
| 公开回复通道、投递状态、关联 ID | 未接入 | 不把内部请求或工具输出发送到聊天/TTS |
| Grounder、轨迹、ROS ACK、物理判定 | 未接入 | 真实控制端提供受控观测或 actions details |

浏览器不连接 ZMQ、数据库或模型端口。不从历史 Goal 推算任务队列、步骤总数或百分比。后续只为真实 HTTP 字段增加映射。

Laya 进程和健康检查使用已有替身。需要动作时只使用隔离 Mock Actor。异常展示使用明确标记的 HTTP 响应 fixture，正常页面无测试数据源。具体通过数、失败记录和截图见 [B09 报告](../B09_DECISION_UI_RESULT.md)。
